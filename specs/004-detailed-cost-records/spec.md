# Feature Specification: 详细成本核算记录

**Feature Branch**: `004-detailed-cost-records`
**Created**: 2026-01-31
**Status**: Draft
**Input**: 用户描述: "在充分理解当前项目的基础上，实现IPC场景下AWS成本评估的详细核算记录功能。用户在前端填写影响成本计算的相关因素，系统根据AWS定价模型计算成本，生成详细完整、可归因分析的核算信息。核算信息存储在DynamoDB中，并可在前端呈现。要求成本核算因素结构清晰、便于理解，详细核算信息全面反映中间数据，让用户可以回溯每项费用的计算过程。"

## Clarifications

### Session 2026-01-31

- Q: 列表分页每页默认显示多少条记录？ → A: 每页20条记录（与现有evaluations功能保持一致）
- Q: 列表搜索筛选支持哪些条件？ → A: 仅支持按名称搜索（保持简单）
- Q: 实时预览详细核算的触发方式？ → A: 输入停止500ms后自动计算（防抖方式）
- Q: 默认值的来源？ → A: 内置典型场景默认值（如10台设备、30天保留、1080p画质）
- Q: 详细核算信息的展示位置？ → A: 输入表单下方内联展示（单列布局）
- Q: 实时预览是否需要登录？ → A: 无需登录即可使用实时预览，保存时才需要登录

## User Scenarios & Testing *(mandatory)*

### User Story 0 - 实时预览详细核算 (Priority: P1)

用户在填写成本计算参数时，系统提供合理的默认值，当用户修改任何参数后，前端实时显示详细的成本核算信息，包括中间计算过程和费用明细，让用户即时理解参数变化对成本的影响。

**Why this priority**: 这是核心用户体验，让用户在保存记录前就能看到完整的计算过程，实现"边填写边理解"的交互模式。

**Independent Test**: 可以通过修改任意输入参数并验证详细核算信息在500ms内自动更新来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户访问成本计算页面，**When** 页面加载完成，**Then** 所有输入参数显示合理的默认值，并自动展示基于默认值的详细核算信息
2. **Given** 用户正在填写参数，**When** 用户修改任意参数并停止输入500ms，**Then** 系统自动重新计算并更新详细核算信息展示
3. **Given** 详细核算信息展示区域，**When** 计算完成，**Then** 展示完整的中间计算指标、分阶段费用明细（单价×用量=金额）、费用汇总
4. **Given** 用户修改参数触发计算，**When** 计算正在进行中，**Then** 展示加载状态指示器（如旋转图标），保留上次计算结果但显示为半透明
5. **Given** 实时计算过程中发生错误，**When** 错误返回，**Then** 显示错误提示信息并保留上次成功的计算结果，用户可修改参数重试

---

### User Story 1 - 生成详细核算记录 (Priority: P1)

用户在预览详细核算信息后，可以选择将当前计算结果保存为核算记录，该记录包含完整的输入参数、中间计算过程和最终费用明细，以便日后回溯和审计成本计算的正确性。

**Why this priority**: 这是核心功能，没有生成能力，其他功能（查看、管理）都无法实现。用户的主要诉求是"可归因分析"，需要看到完整的计算过程。

**Independent Test**: 可以通过在成本计算页面点击"保存核算记录"按钮并验证记录被成功创建和保存来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户已完成一次成本计算且已登录，**When** 用户点击"保存核算记录"按钮并输入记录名称，**Then** 系统生成包含完整计算过程的核算记录并显示成功提示
2. **Given** 用户正在生成核算记录，**When** 系统处理完成，**Then** 记录包含以下信息：输入参数快照、中间计算指标、分阶段费用明细、费用汇总、定价数据快照
3. **Given** 生成的核算记录，**When** 用户查看费用明细，**Then** 每项费用都显示计算公式（单价 × 用量 = 金额）

---

### User Story 2 - 查看核算记录详情 (Priority: P1)

用户需要查看已保存的核算记录详情，包括完整的输入参数、计算中间值、分阶段费用明细等，以理解每一项费用是如何计算得到的。

**Why this priority**: 这是"可归因分析"的核心体验，用户生成记录后必须能看到详细内容才能理解费用构成。

**Independent Test**: 可以通过访问核算记录详情页面并验证所有信息正确展示来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在核算记录列表页，**When** 用户点击某条记录，**Then** 系统跳转到详情页面展示完整核算信息
2. **Given** 用户在核算记录详情页，**When** 页面加载完成，**Then** 展示以下区块：基本信息、输入参数（三维度）、中间计算指标、分阶段费用表格、费用汇总饼图、定价快照
3. **Given** 详情页的分阶段费用表格，**When** 用户展开某个阶段，**Then** 显示该阶段的存储费用、请求费用、检索费用、转换费用的详细计算（单价、用量、金额）

---

### User Story 3 - 管理核算记录列表 (Priority: P2)

用户需要查看和管理自己的核算记录历史，包括浏览列表、按名称搜索和删除不需要的记录。

**Why this priority**: 列表管理是辅助功能，帮助用户组织和查找历史记录，但不是核心的"可归因分析"功能。

**Independent Test**: 可以通过访问核算记录列表页面并测试列表展示、排序、删除功能来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 用户访问核算记录列表页，**Then** 系统展示该用户的所有核算记录，按创建时间倒序排列
2. **Given** 核算记录列表，**When** 用户点击删除按钮并确认，**Then** 系统删除该记录并更新列表
3. **Given** 核算记录列表，**When** 记录为空，**Then** 系统显示空状态提示和引导用户去计算器页面生成记录

---

### User Story 4 - 输入参数结构化展示 (Priority: P2)

用户需要在详情页清晰地看到成本计算的输入参数，分为功能维度、技术维度、价格维度三类，便于理解各参数对成本的影响。

**Why this priority**: 输入参数展示是详情页的重要组成部分，帮助用户理解"为什么这样计算"，但核心体验在于计算过程和结果。

**Independent Test**: 可以通过查看详情页的输入参数区块并验证三类维度正确分组展示来独立测试。

**Acceptance Scenarios**:

1. **Given** 核算记录详情页，**When** 用户查看输入参数区块，**Then** 参数按三个维度分类展示：功能维度（设备数、录像模式等）、技术维度（存储类型、生命周期策略）、价格维度（区域、折扣）
2. **Given** 输入参数展示，**When** 参数包含枚举值，**Then** 显示中文友好标签而非技术代码

---

### Edge Cases

**按钮状态控制**：
- 当用户未登录时点击"保存核算记录"会发生什么？
  - 显示登录提示，引导用户登录后再保存
- 当计算正在进行中时点击"保存核算记录"会发生什么？
  - 按钮显示为禁用状态，直到计算完成
- 当计算结果为错误状态时点击"保存核算记录"会发生什么？
  - 按钮显示为禁用状态，用户需先修正输入参数

**数据展示**：
- 当记录中的定价数据与当前最新定价不同时如何展示？
  - 详情页显示记录时的定价快照，明确标注"定价快照日期"
- 当使用单一存储类型（非生命周期）时，分阶段费用如何展示？
  - 仅展示一个阶段，阶段名称显示为"全周期 (第1天-第N天)"

**错误处理**：
- 当生成记录过程中网络中断会发生什么？
  - 显示错误提示，用户可重试生成
- 当用户删除记录后又想恢复怎么办？
  - 删除前显示确认对话框，删除后无法恢复（设计约束：保持简单，仅支持CRD）
- 当定价数据不可用（API 失败）时实时预览如何处理？
  - 使用本地回退定价数据继续计算，显示提示"使用本地定价数据（可能非最新）"
- 当详情页加载失败（记录不存在或无权限）时如何处理？
  - 显示 404 或 403 错误页面，提供返回列表的链接

**容量限制**：
- 当用户已保存 1000 条记录（达到上限）时如何处理？
  - 显示提示"已达到存储上限（1000条），请删除旧记录后再保存"，"保存核算记录"按钮禁用

**并发与会话**：
- 当用户在多个标签页同时操作核算记录时如何处理？
  - 各标签页独立操作，列表页刷新时显示最新数据，无需特殊冲突处理
- 当用户保存记录时 JWT 会话过期如何处理？
  - 显示会话过期提示，引导用户重新登录，保存操作需重新执行

**输入验证**：
- 当记录名称包含特殊字符（emoji、HTML 标签等）时如何处理？
  - 允许 emoji，HTML 标签将被转义显示，名称长度按字符数计算（非字节数）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-000**: 系统必须为所有成本计算输入参数提供内置典型场景默认值，页面加载后立即显示基于默认值的详细核算信息。完整默认值列表：
  - 功能维度：设备数=10，录像模式=事件触发，视频质量=1080p，保留天数=30，每日事件数=50，事件时长=30秒，回看比例=0.1
  - 技术维度：存储类型=S3 Standard，分片策略=固定时长，分片时长=10秒，生命周期=禁用
  - 价格维度：区域=us-east-1，折扣=0%
- **FR-000a**: 系统必须在用户修改任意输入参数并停止输入500ms后，自动重新计算并更新详细核算信息展示（防抖机制）
- **FR-000b**: 系统必须在成本计算页面输入表单下方内联展示详细核算信息（单列布局），按以下顺序分区块展示：
  1. 中间计算指标（分两组：数据量指标、请求数指标）
  2. 分阶段费用表格（单一存储类型时显示为"全周期"单阶段）
  3. 费用汇总（含饼图）
- **FR-000c**: 系统必须在实时计算过程中显示加载状态指示器，计算失败时显示错误提示并保留上次成功结果
- **FR-001**: 系统必须在成本计算页面提供"保存核算记录"按钮，仅在以下条件全部满足时启用：用户已登录、计算已完成、计算无错误、未达到存储上限
- **FR-002**: 系统必须在生成记录时收集用户输入的名称（必填，最多100字符）和描述（可选，最多500字符）
- **FR-003**: 系统必须完整保存计算时的输入参数快照，包括功能维度、技术维度、价格维度的所有参数
- **FR-004**: 系统必须保存详细的中间计算指标，包括：每日数据量(KB/GB)、平均存储量(GB/TB)、每日分片数、月度PUT/GET请求数、月度检索量、月度传输量
- **FR-005**: 系统必须保存分阶段费用明细，每阶段包含：时间范围、存储类型、存储费用、请求费用、检索费用、转换费用，每项费用包含单价、用量、金额
- **FR-006**: 系统必须保存费用汇总，包括：各项费用金额、费用占比、小计、折扣金额、总计、单设备成本、单GB成本
- **FR-007**: 系统必须保存计算时的定价数据快照，包括：区域、货币、快照日期、各存储类型单价、数据传输阶梯定价
- **FR-008**: 系统必须提供核算记录列表功能，支持按用户查询、分页（默认每页20条）、按创建时间排序
- **FR-009**: 系统必须提供核算记录详情查看功能，展示单条记录的完整信息
- **FR-010**: 系统必须提供删除核算记录功能，仅允许用户删除自己的记录
- **FR-011**: 系统必须在前端提供核算记录列表页面，展示记录名称、存储策略、总成本、创建时间；加载时显示骨架屏，加载失败时显示错误提示和重试按钮
- **FR-012**: 系统必须在前端提供核算记录详情页面，按以下顺序分区块展示：
  1. 基本信息（名称、描述、创建时间、存储策略）
  2. 输入参数（三维度卡片布局：功能维度 | 技术维度 | 价格维度）
  3. 中间计算指标（两组：数据量指标、请求数指标）
  4. 分阶段费用表格（可折叠展开每阶段详情）
  5. 费用汇总（含占比饼图）
  6. 定价快照（折叠面板，默认收起）
  加载失败时显示 404/403 错误页面
- **FR-012a**: 详情页与实时预览组件的信息结构必须保持一致，确保用户在保存前后看到相同格式的核算信息
- **FR-013**: 系统必须允许未登录用户使用实时预览功能；保存、查看、删除核算记录功能仅限已登录用户使用

### Key Entities *(include if feature involves data)*

- **CalculationRecord (核算记录)**: 详细成本核算的完整记录，包含记录ID、用户ID、名称、描述、创建时间、存储策略类型、输入参数快照、中间指标、分阶段费用、费用汇总、定价快照。关联到创建该记录的用户。
- **InputParameterSnapshot (输入参数快照)**: 记录计算时的三类维度参数（功能维度、技术维度、价格维度），用于完整还原计算条件。
- **IntermediateMetrics (中间计算指标)**: 计算过程中产生的中间数据，包括每日数据量、平均存储量、请求数等，用于展示计算推导过程。
- **StageCostDetail (阶段费用明细)**: 生命周期中单个存储阶段的费用详情，包含阶段时间范围、存储类型、各项费用的单价、用量、金额。
- **PricingSnapshot (定价快照)**: 计算时捕获的AWS定价数据，包括区域、货币、快照日期、各存储类型定价、数据传输阶梯定价。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从点击"保存核算记录"按钮到看到成功提示的时间不超过3秒（测量起点：按钮点击事件触发；终点：成功 Toast 显示；不包含对话框输入时间）
- **SC-002**: 核算记录详情页在1秒内完成加载和渲染（测量条件：网络延迟 <100ms、记录数据量 <100KB；测量起点：路由跳转触发；终点：所有区块内容渲染完成）
- **SC-003**: 详情页中每项费用都清晰展示计算公式"单价 × 用量 = 金额"，数值精度保持到小数点后4位（验证方法：自动化测试检查公式元素存在性和数值正确性）
- **SC-004**: 核算记录详情页展示的费用数据与原始计算结果100%一致（通过 E2E 测试验证）
- **SC-005**: 系统能支持单用户保存最多1000条核算记录，达到上限时系统正常拒绝新增并提示用户
- **SC-006**: 列表页支持按创建时间排序，正确性达100%
- **SC-007**: 实时预览计算响应时间不超过500ms（测量条件：防抖触发后到结果渲染完成；不包含防抖等待时间）

### Non-Functional Requirements

- **NFR-001**: 实时预览计算响应时间不超过500ms（从防抖触发到结果渲染）
- **NFR-002**: 单条核算记录数据大小不超过 200KB（预留 DynamoDB 400KB 限制的安全余量）
- **NFR-003**: 列表页在用户有 1000 条记录时，首页加载时间不超过 2 秒
- **NFR-004**: 核算记录数据通过 HTTPS 加密传输，存储在 DynamoDB 时无额外加密需求（记录不包含敏感个人信息）
- **NFR-005**: 记录名称和描述字段需进行 XSS 防护（HTML 转义）

## Assumptions

- 现有 `LifecycleCalculator.calculate_with_details()` 方法已返回 `DetailedCostBreakdown`，可直接复用
- 现有 `S3StandardCalculator.calculate()` 需要扩展以支持返回详细明细（技术任务，在 plan.md 中跟踪）
- 实时预览功能无需登录；保存、查看、删除核算记录功能需要登录
- 核算记录仅支持创建(Create)、读取(Read)、删除(Delete)操作，不支持更新（保持记录不可篡改）
- 删除操作为硬删除，不可恢复
- 定价快照保存完整的定价数据，而非仅保存定价ID或引用
- 核算记录功能独立于现有的 evaluations 功能：
  - 独立的 DynamoDB 表 (`ipc_cost_calculation_records`)
  - 独立的 API 路由 (`/api/v1/calculation-records`)
  - 独立的前端页面 (`/calculation-records`, `/calculation-records/:id`)
  - 可复用通用 UI 组件（如 Layout、LoadingSpinner、骨架屏）
  - 导航栏新增独立入口
