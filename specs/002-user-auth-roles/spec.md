## Clarifications

### Session 2026-01-26

- Q: 密码最低强度要求是什么？ → A: 最低8位，需包含字母和数字
- Q: 初始管理员账号如何创建？ → A: 通过环境变量配置初始管理员邮箱和密码

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 访客使用成本计算器 (Priority: P1)

访客无需登录即可使用系统的核心成本计算功能。访客可以输入设备参数和存储配置，进行成本计算和方案对比，但无法保存评估记录。

**Why this priority**: 核心业务价值——让任何用户都能快速试用系统，评估 IPC 云存储成本，降低使用门槛，吸引潜在用户

**Independent Test**: 在未登录状态下访问计算功能，输入参数后获得成本计算结果

**Acceptance Scenarios**:

1. **Given** 用户未登录, **When** 用户访问成本计算页面并输入有效参数, **Then** 系统返回完整的成本计算结果
2. **Given** 用户未登录, **When** 用户使用方案对比功能, **Then** 系统返回 S3 Standard、Glacier IR 和生命周期策略的对比结果
3. **Given** 用户未登录, **When** 用户尝试保存评估记录, **Then** 系统提示需要登录后才能保存

---

### User Story 2 - 用户注册与登录 (Priority: P1)

用户可以通过邮箱注册账号并登录系统，获得更多功能权限。登录后用户可以保存和管理自己的评估记录。

**Why this priority**: 身份认证是角色权限系统的基础，没有登录功能就无法区分用户角色

**Independent Test**: 新用户完成注册流程并成功登录系统

**Acceptance Scenarios**:

1. **Given** 用户未注册, **When** 用户提供有效邮箱和密码完成注册, **Then** 用户成功创建账号并自动登录
2. **Given** 用户已注册, **When** 用户输入正确的邮箱和密码, **Then** 用户成功登录并进入系统
3. **Given** 用户已登录, **When** 用户点击退出登录, **Then** 用户会话结束，返回访客状态
4. **Given** 用户登录失败3次, **When** 用户继续尝试登录, **Then** 系统暂时限制该账号的登录尝试

---

### User Story 3 - 登录用户管理评估记录 (Priority: P2)

登录用户可以保存、查看、编辑和删除自己的评估记录。用户可以创建分享链接将评估结果分享给他人。

**Why this priority**: 这是登录用户相对于访客的核心增值功能，为用户提供持久化和协作能力

**Independent Test**: 登录用户保存一个评估记录，然后在评估历史中找到并加载它

**Acceptance Scenarios**:

1. **Given** 用户已登录, **When** 用户完成成本计算后点击保存, **Then** 评估记录保存成功并出现在用户的历史记录中
2. **Given** 用户已登录且有历史记录, **When** 用户查看评估历史列表, **Then** 系统显示用户所有的评估记录（按时间排序）
3. **Given** 用户已登录, **When** 用户编辑某个评估记录的名称或描述, **Then** 修改成功保存
4. **Given** 用户已登录, **When** 用户为评估记录创建分享链接, **Then** 系统生成可访问的分享链接
5. **Given** 用户已登录, **When** 用户尝试访问其他用户的评估记录, **Then** 系统拒绝访问并返回权限错误

---

### User Story 4 - 管理员管理用户和系统 (Priority: P2)

管理员可以查看所有用户列表、管理用户角色、查看系统使用统计。管理员拥有系统的完整访问权限。

**Why this priority**: 管理员功能是系统治理和运营的基础，但优先级低于核心业务功能

**Independent Test**: 管理员登录后可以查看用户列表并修改某个用户的角色

**Acceptance Scenarios**:

1. **Given** 管理员已登录, **When** 管理员访问用户管理页面, **Then** 系统显示所有用户的列表信息
2. **Given** 管理员已登录, **When** 管理员将某个普通用户的角色改为管理员, **Then** 该用户获得管理员权限
3. **Given** 管理员已登录, **When** 管理员禁用某个用户账号, **Then** 该用户无法登录系统
4. **Given** 管理员已登录, **When** 管理员查看系统统计, **Then** 系统显示用户数量、评估数量等统计信息
5. **Given** 管理员已登录, **When** 管理员刷新定价数据, **Then** 系统重新获取 AWS 定价信息

---

### User Story 5 - 访客访问分享链接 (Priority: P3)

访客可以通过分享链接查看他人分享的评估结果，但只能查看不能编辑。

**Why this priority**: 分享功能增强系统的协作能力，但依赖于登录用户功能

**Independent Test**: 通过分享链接访问评估结果，能看到完整的计算结果但无法编辑

**Acceptance Scenarios**:

1. **Given** 访客拥有有效的分享链接, **When** 访客访问该链接, **Then** 系统显示评估的输入参数和计算结果
2. **Given** 访客拥有有效的分享链接, **When** 访客尝试修改评估内容, **Then** 系统拒绝修改（只读权限）
3. **Given** 分享链接已过期, **When** 访客访问该链接, **Then** 系统显示链接已失效的提示

---

### Edge Cases

- 用户注册时邮箱已被使用？系统提示邮箱已注册，建议登录或找回密码
- 登录会话过期时用户正在操作？系统提示重新登录，保留当前页面状态以便登录后继续
- 管理员尝试删除自己的账号或降低自己的权限？系统拒绝操作，要求其他管理员执行
- 系统只剩一个管理员时尝试降级？系统拒绝，必须保证至少有一个管理员
- 访客在计算页面停留很久但未保存？提供浏览器本地暂存功能，下次访问可恢复

## Requirements *(mandatory)*

### Functional Requirements

**身份认证**
- **FR-001**: 系统 MUST 支持通过邮箱和密码进行用户注册（密码最低8位，需包含字母和数字）
- **FR-002**: 系统 MUST 支持通过邮箱和密码进行用户登录
- **FR-003**: 系统 MUST 验证邮箱格式的有效性
- **FR-004**: 系统 MUST 对密码进行安全存储（不可逆加密）
- **FR-005**: 系统 MUST 支持用户退出登录
- **FR-006**: 系统 MUST 在连续登录失败后临时锁定账号

**角色与权限**
- **FR-007**: 系统 MUST 支持三种用户角色：Admin（管理员）、User（登录用户）、Viewer（访客）
- **FR-008**: 系统 MUST 为每个 API 端点定义所需的最低角色权限
- **FR-009**: 系统 MUST 在用户尝试访问无权限资源时返回明确的错误提示
- **FR-010**: 系统 MUST 默认将新注册用户设置为 User 角色

**访客权限（Viewer）**
- **FR-011**: 访客 MUST 能够使用成本计算功能
- **FR-012**: 访客 MUST 能够使用方案对比功能
- **FR-013**: 访客 MUST 能够查看定价信息和区域列表
- **FR-014**: 访客 MUST 能够查看生命周期模板列表
- **FR-015**: 访客 MUST 能够通过分享链接查看他人的评估结果

**登录用户权限（User）**
- **FR-016**: 登录用户 MUST 拥有访客的所有权限
- **FR-017**: 登录用户 MUST 能够保存评估记录
- **FR-018**: 登录用户 MUST 能够查看、编辑、删除自己的评估记录
- **FR-019**: 登录用户 MUST 能够为自己的评估记录创建分享链接
- **FR-020**: 登录用户 MUST 能够管理自己创建的分享链接
- **FR-021**: 登录用户 MUST 能够修改自己的账号信息（名称、密码）

**管理员权限（Admin）**
- **FR-022**: 管理员 MUST 拥有登录用户的所有权限
- **FR-023**: 管理员 MUST 能够查看系统中所有用户的列表
- **FR-024**: 管理员 MUST 能够修改其他用户的角色
- **FR-025**: 管理员 MUST 能够禁用或启用用户账号
- **FR-026**: 管理员 MUST 能够查看系统使用统计信息
- **FR-027**: 管理员 MUST 能够强制刷新定价数据
- **FR-028**: 系统 MUST 防止最后一个管理员被降级或删除

**会话管理**
- **FR-029**: 系统 MUST 为登录用户创建安全的会话令牌
- **FR-030**: 系统 MUST 支持会话过期自动失效
- **FR-031**: 系统 MUST 在会话过期时引导用户重新登录

### Key Entities

- **用户（User）**: 系统的身份实体，包含邮箱、密码哈希、名称、角色、状态、创建时间
- **角色（Role）**: 权限级别定义，包括 Admin、User、Viewer 三种类型
- **会话（Session）**: 用户登录状态的表示，包含令牌、过期时间、关联用户
- **权限（Permission）**: API 端点与所需角色的映射关系

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 访客可以在 10 秒内完成一次完整的成本计算流程
- **SC-002**: 用户可以在 30 秒内完成注册并成功登录
- **SC-003**: 登录用户保存评估记录后，可以在 5 秒内从历史记录中找到并加载
- **SC-004**: 系统正确阻止 100% 的未授权资源访问尝试
- **SC-005**: 用户登录失败 3 次后触发账号临时锁定
- **SC-006**: 管理员可以在用户列表中看到所有用户并进行角色管理
- **SC-007**: 分享链接在有效期内访问成功率达到 99.9%
- **SC-008**: 会话在设定的过期时间后自动失效
- **SC-009**: 系统支持最多 100 个并发用户正常使用

## Assumptions

- 系统当前已有基础的用户认证框架（邮箱/密码注册登录）
- 系统当前已有评估记录的保存和分享功能
- 会话过期时间默认设置为 24 小时
- 账号锁定时间默认设置为 15 分钟
- 新注册用户默认角色为 User
- 系统初始化时通过环境变量（ADMIN_EMAIL, ADMIN_PASSWORD）配置初始管理员账号

## Out of Scope

- 第三方登录（Google、GitHub OAuth）
- 双因素认证（2FA）
- 密码找回/重置功能
- 用户头像和详细个人资料
- 细粒度权限控制（基于资源的权限）
- 审计日志和操作记录
