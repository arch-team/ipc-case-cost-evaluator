# Feature Specification: IPC Case Cost Evaluator - AWS S3 云存储成本评估系统

**Feature Branch**: `001-ipc-cost-evaluator`
**Created**: 2026-01-25
**Status**: Draft
**Input**: User description: "基于当前项目的实现来生成spec.md"

## 概述

IPC Case Cost Evaluator 是一个面向企业在典型复杂场景下AWS云服务成本评估系统。该系统帮助安防监控领域的技术决策者和成本规划人员，通过输入 IPC（网络摄像头）监控场景参数，精确计算不同AWS存储方案的成本，并提供优化建议，从而做出更明智的云存储选型决策。

## Clarifications

### Session 2026-01-25

- Q: 用户认证采用什么方式？ → A: JWT Token 认证（适合 API-First 架构，无状态，易于扩展）
- Q: 系统需要什么级别的可观测性支持？ → A: 暂不需要（简单成本计算工具，后续按需添加）
- Q: 评估历史和分享链接的数据存储方式？ → A: Amazon DynamoDB（与 AWS 生态一致，Serverless，按需扩展）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 单一存储方案成本计算 (Priority: P1)

用户作为安防系统架构师，需要快速了解当前监控场景下使用 S3 Standard 或 S3 Glacier IR 存储视频数据的月度/年度成本。用户通过填写三类维度参数（功能维度：设备数量、录像模式、视频质量等；技术维度：存储类型、生命周期策略；价格维度：区域、折扣），系统立即计算出详细的费用明细，包括存储费、请求费、检索费、传输费等各项成本构成。

**Why this priority**: 成本计算是系统的核心价值。无论后续功能如何扩展，用户首先需要能够获得准确的成本估算。这是所有其他功能的基础。

**Independent Test**: 用户仅使用此功能即可获得完整的成本估算报告，了解具体费用明细和月度/年度成本汇总。

**Acceptance Scenarios**:

1. **Given** 用户已进入计算器页面，**When** 用户输入 100 台 1080p 摄像头、事件触发录像、30 天保留期、S3 Standard 存储，**Then** 系统显示存储费、PUT 请求费、GET 请求费等各项费用明细，以及月度和年度总成本。

2. **Given** 用户已完成参数输入，**When** 用户修改任意参数（如将设备数量从 100 改为 200），**Then** 系统立即重新计算并更新费用显示，无需用户手动触发。

3. **Given** 用户输入不合理参数（如负数设备数量），**When** 用户尝试计算，**Then** 系统提示参数验证错误，明确指出错误字段和原因。

---

### User Story 2 - 多存储方案对比分析 (Priority: P1)

用户需要同时对比 S3 Standard、S3 Glacier IR 和生命周期策略（如先用 Standard 存 7 天再转 Glacier）多种方案的成本差异，以便选择最优的存储策略。系统自动计算各方案成本，显示对比图表和节省比例，并提供优化建议。

**Why this priority**: 方案对比是用户做出决策的关键依据。单一方案计算虽然重要，但用户最终需要通过对比才能确定最佳方案。与 P1 并列因为两者共同构成核心价值。

**Independent Test**: 用户可完全独立使用此功能，一次输入参数即可看到多个方案的成本对比结果和推荐建议。

**Acceptance Scenarios**:

1. **Given** 用户已输入监控场景参数，**When** 用户选择「方案对比」模式，**Then** 系统同时显示 S3 Standard、S3 Glacier IR、以及推荐的生命周期策略三种方案的成本明细和对比图表。

2. **Given** 用户查看对比结果，**When** 系统完成计算，**Then** 显示各方案相对于最高成本方案的节省百分比，并标注推荐方案。

3. **Given** 用户使用低回看率场景参数，**When** 系统分析完成，**Then** 系统推荐使用 Glacier IR 或生命周期策略，并解释推荐理由。

---

### User Story 3 - 生命周期多阶段策略配置 (Priority: P2)

用户需要配置复杂的多阶段生命周期策略，例如：前 7 天用 S3 Standard（高频访问期）、8-30 天转 S3 Glacier IR（低频期）、31-90 天转 Deep Archive（归档期）。系统提供可视化的阶段编辑器，用户可灵活添加、删除和调整各阶段的存储类型和时长。系统还提供预设的生命周期模板（短期 30 天、中期 90 天、长期 365 天），用户可一键加载模板后再根据实际需求微调各阶段参数。

**Why this priority**: 多阶段策略是进阶用户的需求，对于有精细化成本优化需求的企业客户至关重要，但不影响基础的单阶段计算功能。

**Independent Test**: 用户可仅使用多阶段配置功能创建复杂的生命周期策略并获得成本估算。

**Acceptance Scenarios**:

1. **Given** 用户进入生命周期配置界面，**When** 用户添加三个阶段（Standard 7天 → Glacier IR 23天 → Deep Archive 60天），**Then** 系统正确计算各阶段的存储费用、转换费用，并显示总成本。

2. **Given** 用户已配置多阶段策略，**When** 用户调整某阶段的天数（如将 Standard 从 7 天改为 14 天），**Then** 后续阶段自动调整，总保留天数保持不变（或提示用户确认调整方式）。

3. **Given** 用户配置的阶段天数总和超出保留期，**When** 用户保存配置，**Then** 系统提示错误并要求调整阶段配置。

4. **Given** 用户进入生命周期配置界面，**When** 用户从模板库选择「90 天中期模板」，**Then** 系统自动填充三阶段配置（Standard 14天 → Glacier IR 46天 → Deep Archive 30天），用户可继续编辑各阶段参数。

---

### User Story 4 - 预设场景快速加载 (Priority: P2)

用户作为初次使用者，不熟悉各参数的合理取值。系统提供预设的典型场景（如「小型门店监控」、「中型办公楼监控」、「大型园区监控」），用户一键加载即可自动填充所有参数，然后根据实际情况微调。

**Why this priority**: 显著降低新用户的学习门槛，提升产品易用性。但即使没有预设场景，用户仍可手动输入参数完成计算。

**Independent Test**: 新用户可仅依靠预设场景快速获得成本估算，无需了解每个参数的含义。

**Acceptance Scenarios**:

1. **Given** 用户进入计算器页面，**When** 用户从场景库选择「中型办公楼监控（50台 1080p）」，**Then** 所有参数自动填充（设备数=50，视频质量=1080p，录像模式=事件触发，保留期=30天等）。

2. **Given** 用户已加载预设场景，**When** 用户修改部分参数（如将设备数从 50 改为 80），**Then** 系统使用修改后的参数进行计算，不影响预设场景本身。

---

### User Story 5 - 评估结果导出与分享 (Priority: P3)

用户完成成本评估后，需要将结果导出为 Excel 格式用于内部汇报，或生成分享链接发送给同事或领导审阅。导出的报告包含完整的参数配置、费用明细、对比分析和图表。

**Why this priority**: 属于输出增强功能，提升专业性和协作便利性，但核心的计算和对比功能可独立于此运作。

**Independent Test**: 用户可独立使用导出功能生成标准格式的成本报告文件。

**Acceptance Scenarios**:

1. **Given** 用户已完成成本计算，**When** 用户点击「导出 Excel」，**Then** 系统生成包含所有参数、费用明细、对比结果的格式化 Excel 文件并下载。

2. **Given** 用户已完成成本计算，**When** 用户点击「生成分享链接」，**Then** 系统生成带有效期的只读链接，其他用户通过链接可查看相同的评估结果。

3. **Given** 分享链接已过期，**When** 访问者点击链接，**Then** 系统显示「链接已过期」提示，引导用户联系分享者获取新链接。

---

### User Story 6 - 评估历史记录管理 (Priority: P3)

用户需要保存和管理历史评估记录，以便后续查阅、修改或对比不同时期的评估结果。系统为已登录用户提供评估记录的保存、查看、编辑和删除功能。

**Why this priority**: 为用户提供持久化能力，支持长期使用和历史对比，但基础计算功能不依赖此特性。

**Independent Test**: 用户可独立使用历史记录功能管理所有已保存的评估。

**Acceptance Scenarios**:

1. **Given** 用户已登录并完成计算，**When** 用户点击「保存评估」，**Then** 系统将当前参数和结果保存到用户的评估历史中。

2. **Given** 用户有多条历史记录，**When** 用户进入「评估历史」页面，**Then** 系统以列表形式展示所有记录，包含名称、创建时间、主要参数摘要。

3. **Given** 用户选择一条历史记录，**When** 用户点击「加载」，**Then** 系统恢复该记录的所有参数到计算器，用户可继续修改或重新计算。

---

### User Story 7 - AWS 实时定价数据更新 (Priority: P3)

系统管理员需要保持定价数据与 AWS 官方价格同步。系统集成 AWS Pricing API，支持手动触发定价数据刷新，确保成本计算的准确性。

**Why this priority**: 定价数据的准确性影响计算结果的可信度，但系统已内置默认定价数据，刷新功能属于维护性功能。

**Independent Test**: 管理员可独立触发定价刷新，验证数据已更新到最新版本。

**Acceptance Scenarios**:

1. **Given** 管理员进入定价管理界面，**When** 管理员点击「刷新定价数据」，**Then** 系统调用 AWS Pricing API 获取最新价格，更新本地定价数据。

2. **Given** 定价刷新完成，**When** 用户进行新的成本计算，**Then** 系统使用更新后的定价数据进行计算。

3. **Given** AWS Pricing API 不可用，**When** 管理员尝试刷新，**Then** 系统显示错误提示并继续使用现有定价数据。

---

### User Story 8 - 成本敏感度分析 (Priority: P2)

用户完成成本计算后，希望了解哪些参数对总成本影响最大，以便在实际部署时优先控制关键变量。系统提供参数调节模拟器，用户通过滑块调节参数值，实时查看成本变化的数值对比和趋势曲线。

**Why this priority**: 帮助用户做出更明智的成本优化决策，识别"成本杀手"参数，但不影响基础计算功能。

**Independent Test**: 用户可独立使用敏感度分析功能，探索不同参数组合对成本的影响。

**Acceptance Scenarios**:

1. **Given** 用户已完成成本计算，**When** 用户进入敏感度分析面板，**Then** 系统显示 5 个可调节参数（设备数量、保留天数、回看比例、视频质量、录像模式）的滑块控件。

2. **Given** 用户拖动"设备数量"滑块从 100 调整到 200，**When** 滑块释放，**Then** 系统立即显示成本变化：原成本 → 调整后成本（含差额和百分比），同时更新下方的成本变化曲线图。

3. **Given** 用户查看成本变化曲线图，**When** 曲线渲染完成，**Then** 横轴显示参数值范围（0.5x ~ 2.0x），纵轴显示月度成本，当前选择点在曲线上高亮标注。

---

### Edge Cases

- **极端参数处理**：当设备数量为 0 或保留天数为 0 时，系统应返回零成本而非报错。
- **超大规模计算**：当设备数量超过 10000 台时，系统应能正常计算且响应时间不超过用户预期。
- **区域定价缺失**：当用户选择的 AWS 区域没有定价数据时，系统应提示并建议使用相近区域或刷新定价。
- **生命周期冲突**：当用户配置的转换天数大于保留天数时，系统应阻止并提示错误。
- **并发访问**：多用户同时计算时，各用户的结果应相互独立，不产生数据混乱。
- **精度控制**：成本计算结果应保留合理的小数位数（如 2 位），避免浮点精度问题导致的显示异常。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持用户输入功能维度参数，包括设备数量（1-100000）、录像模式（连续/事件触发/计划录像）、视频质量（720p/1080p/2K/4K）、每日事件数、事件时长、回看比例（0-100%）、保留天数（1-365天）和分段策略。分段策略包括三种模式：
  - **固定时长**：每 N 秒生成一个文件（N 可配置，范围 10-300 秒，默认 60 秒）
  - **固定大小**：每 N MB 生成一个文件（N 可配置，范围 1-100 MB，默认 10 MB）
  - **实时流**：持续写入单文件，适合边缘存储场景

  分段策略直接影响 PUT 请求数量计算，用户应根据实际设备固件能力选择合适的策略。

- **FR-002**: 系统必须支持用户选择技术维度参数，包括存储类型（S3 Standard/S3 Glacier IR/S3 Deep Archive）和生命周期策略配置。

- **FR-003**: 系统必须支持用户配置价格维度参数，包括 AWS 区域选择、企业折扣比例和计费模式。

- **FR-004**: 系统必须能够根据输入参数计算月度存储费用、PUT 请求费用、GET 请求费用、数据检索费用、数据传输费用和生命周期转换费用，并汇总为总成本。

- **FR-005**: 系统必须提供多方案对比功能，同时计算至少三种存储方案（Standard、Glacier IR、生命周期策略）的成本并展示对比结果。

- **FR-006**: 系统必须支持多阶段生命周期策略配置，允许用户定义 2-5 个存储阶段，每个阶段指定存储类型和时长。

- **FR-007**: 系统必须提供预设场景库，包含至少 5 个典型监控场景的参数预设，用户可一键加载。

- **FR-008**: 系统必须支持将评估结果导出为格式化的 Excel 文件，包含参数配置、费用明细和对比分析。

- **FR-009**: 系统必须支持生成带有效期的分享链接，链接默认有效期为 7 天。

- **FR-010**: 系统必须为已认证用户提供评估历史记录的保存、查看、加载和删除功能。

- **FR-011**: 系统必须支持多个 AWS 区域的定价数据，至少包含 ap-northeast-1（东京）区域。

- **FR-012**: 系统必须提供定价数据刷新接口，支持从 AWS Pricing API 获取最新价格。

- **FR-013**: 系统必须以图表形式可视化展示费用构成（如饼图）和方案对比结果（如柱状图）。

- **FR-014**: 系统必须提供基于 JWT Token 的用户认证功能，支持用户注册、登录、Token 刷新和会话管理，Token 有效期可配置。

- **FR-015**: 系统必须对所有用户输入进行验证，拒绝不合理的参数值并提供明确的错误提示。

- **FR-016**: 系统必须提供成本敏感度分析功能，支持用户通过参数调节模拟器（滑块）实时查看设备数量、保留天数、回看比例、视频质量、录像模式等参数变化对总成本的影响，并以数值对比和曲线图两种形式展示。

### Key Entities

- **功能维度 (FunctionalDimensions)**: 描述监控场景的业务参数，包括设备数量、录像模式、视频质量、事件参数、访问模式、保留期限和分片策略。

- **技术维度 (TechnicalDimensions)**: 描述存储技术选型，包括存储类型和生命周期策略配置。

- **价格维度 (PricingDimensions)**: 描述定价相关配置，包括 AWS 区域、折扣比例和计费模式。

- **生命周期阶段 (LifecycleStage)**: 描述单个存储周期阶段，包括阶段名称、存储类型和持续天数。

- **费用明细 (CostBreakdown)**: 描述单个方案的成本构成，包括各类费用项及其金额。

- **成本汇总 (CostSummary)**: 描述计算结果，包括费用明细、月度总成本、年度总成本和中间计算指标。

- **对比结果 (ComparisonResult)**: 描述多方案对比结果，包括各方案的成本汇总和推荐建议。

- **评估记录 (Evaluation)**: 描述用户保存的评估，包括名称、输入参数、计算结果和创建时间。

- **分享链接 (Share)**: 描述评估分享记录，包括链接标识、关联评估、创建时间和过期时间。

- **区域定价 (RegionalPricing)**: 描述特定 AWS 区域的定价数据，包括各存储类型的存储单价、请求单价、检索单价等。

- **敏感度分析结果 (SensitivityResult)**: 描述参数变化对成本的影响，包括参数名称、基准值、变化范围、对应的成本变化数值和百分比。

- **生命周期模板 (LifecycleTemplate)**: 描述预设的生命周期策略模板，包括模板名称、适用场景描述、包含的阶段配置列表。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开页面到获得首次成本计算结果的操作时间不超过 60 秒（假设用户熟悉参数含义）。

- **SC-002**: 用户修改单个参数后，系统重新计算并更新结果的响应时间不超过 2 秒。

- **SC-003**: 用户使用预设场景功能后，一键加载参数到获得计算结果的时间不超过 5 秒。

- **SC-004**: 系统支持至少 100 个并发用户同时进行成本计算，响应时间保持在可接受范围内。

- **SC-005**: 成本计算准确度：对于相同输入参数，系统计算结果与 AWS 官方计算器结果的偏差不超过 5%。

- **SC-006**: Excel 导出功能生成的报告能够被主流电子表格软件（Excel、Google Sheets）正确打开和显示。

- **SC-007**: 90% 的新用户能够在不查阅帮助文档的情况下完成首次成本评估。

- **SC-008**: 用户对成本明细的各项费用构成能够清晰理解，图表可视化直观反映费用占比。

- **SC-009**: 分享链接在有效期内可被无限次访问，访问者无需登录即可查看完整评估结果。

- **SC-010**: 评估历史记录功能支持用户保存至少 50 条评估记录，并能快速检索和加载历史数据。

## Assumptions

- 用户具备基本的 AWS S3 存储概念知识，了解存储类型和生命周期的含义。
- AWS 定价数据通过 AWS Pricing API 获取，需要有效的 AWS 访问凭证。
- 默认定价数据基于 ap-northeast-1（东京）区域，其他区域的定价数据可通过刷新功能获取。
- 视频比特率参数基于行业标准 H.264/H.265 编码的典型值。
- 系统部署在可访问 AWS 服务的网络环境中。
- 数据传输出站费用仅计算前 10TB 的费率，超出部分使用分层定价计算。
- 用户数据（评估历史、分享链接）存储在 Amazon DynamoDB 中，需要配置相应的 AWS 访问权限。

## Out of Scope

- 非 AWS 云服务商的存储成本计算（如 Azure Blob Storage、Google Cloud Storage）。
- 视频编码和转码的计算资源成本。
- 网络带宽成本（摄像头到云端的上行带宽）。
- AWS 其他相关服务成本（如 Lambda、CloudFront、Rekognition）。
- 多租户企业版功能（组织级管理、批量评估）。
- 实时监控和告警功能。
- 移动端应用。
