# IPC 云存储成本评估 - 用户视角因素与模板

## 用户视角：影响成本的 4 大核心因素

### 因素概览

| 核心因素 | 用户关心的问题 | 成本影响权重 |
|---------|---------------|-------------|
| **业务规模** | 有多少台摄像头？ | ⭐⭐⭐⭐⭐ |
| **使用场景** | 什么时候录像？录什么质量？ | ⭐⭐⭐⭐⭐ |
| **访问需求** | 多久看一次录像？ | ⭐⭐⭐ |
| **保留策略** | 录像保留多久？怎么存？ | ⭐⭐⭐⭐ |

---

### 1. 业务规模

```
设备数量 → 所有成本线性放大

用户决策点：
├─ 小型  (1-50台)    → 智能家居、小型店铺
├─ 中型  (50-200台)  → 商超、办公楼
├─ 大型  (200-1000台)→ 企业园区、小区
└─ 超大型 (1000+台)  → 交通监控、大型园区
```

### 2. 使用场景

```
录像模式 × 视频质量 → 决定每日数据量

录像模式:
├─ 全天候录像   → 数据量最大 (24h × 质量)
├─ 事件触发    → 数据量可控 (事件数 × 时长 × 质量)
└─ 定时段录像   → 中等数据量 (小时数 × 质量)

视频质量:
├─ 720p  → 125 KB/s  (基准)
├─ 1080p → 312 KB/s  (×2.5)
├─ 2K    → 625 KB/s  (×5)
└─ 4K    → 1500 KB/s (×12)
```

### 3. 访问需求

```
回看比例 → 影响 GET/检索/传输成本

用户决策点：
├─ 极少回看 (2-5%)   → 合规存档场景
├─ 偶尔回看 (5-10%)  → 一般监控场景
├─ 经常回看 (10-20%) → 仓储物流、零售
└─ 频繁回看 (20%+)   → 实时监控、家庭安防
```

### 4. 保留策略

```
保留天数 × 存储策略 → 决定存储成本

保留天数:
├─ 短期 (7天)   → 家庭安防
├─ 标准 (30天)  → 一般监控
├─ 中期 (60-90天)→ 企业合规
└─ 长期 (180天+) → 金融/交通

存储策略:
├─ 单一热存储   → 频繁访问，成本最高
├─ 生命周期策略 → 自动转冷，节省 60-90%
└─ 纯冷存储    → 极少访问，成本最低
```

## 预设存储策略模板（技术选型）

| 模板名称 | 保留天数 | 存储策略 | 节省比例 | 适用场景 |
|---------|---------|---------|---------|---------|
| **短期高频** | 7天 | 全程 Standard | 0% | 实时监控、频繁回看 |
| **标准监控** | 30天 | 7天热 + 23天冷 | ~60% | 一般监控、偶尔回看 |
| **合规存储** | 90天 | 7天热 + 30天冷 + 53天归档 | ~75% | 法规合规、审计追溯 |
| **低成本归档** | 180天 | 3天热 + 177天深归档 | ~90% | 极少访问、长期归档 |

### 存储策略详情

#### 短期高频 (7天)
```
└─ [1-7天] S3 Standard
```
- **适用场景**: 实时监控、频繁回看、低延迟访问要求
- **节省比例**: 0%

#### 标准监控 (30天)
```
├─ [1-7天]  S3 Standard     ← 近期高频访问
└─ [8-30天] S3 Glacier IR   ← 低频但可快速检索
```
- **适用场景**: 一般监控、偶尔回看需求、成本敏感用户
- **节省比例**: ~60%

#### 合规存储 (90天)
```
├─ [1-7天]   S3 Standard    ← 近期高频
├─ [8-37天]  S3 Glacier IR  ← 中期偶尔访问
└─ [38-90天] S3 Deep Archive ← 长期归档
```
- **适用场景**: 法规合规要求、长期数据保留、审计追溯需求
- **节省比例**: ~75%

#### 低成本归档 (180天)
```
├─ [1-3天]   S3 Standard     ← 仅保证初期访问
└─ [4-180天] S3 Deep Archive ← 长期深归档
```
- **适用场景**: 极少访问场景、长期归档需求、预算受限用户
- **节省比例**: ~90%

## 成本计算公式

### 每日数据量
```
全天候:   设备数 × 数据速率(KB/s) × 86400秒 / 1024² = GB/天
事件触发: 设备数 × 数据速率(KB/s) × 事件数 × 事件时长 / 1024² = GB/天
定时段:   设备数 × 数据速率(KB/s) × 小时数 × 3600 / 1024² = GB/天
```

### 月度成本
```
总成本 = 存储费 + PUT请求费 + GET请求费 + 检索费 + 传输费 + 生命周期费

存储费   = 平均存储量(GB) × 存储单价
PUT请求费 = 月度PUT次数 / 1000 × PUT单价
GET请求费 = 月度GET次数 / 1000 × GET单价
检索费   = 月度检索量(GB) × 检索单价
传输费   = 月度传输量(GB) × 传输单价
```

### 关键指标
```
平均存储量 = 每日数据量 × 保留天数
月度PUT次数 = 设备数 × 每日分片数 × 30
月度GET次数 = 月度PUT次数 × 回看比例
月度检索量 = 每日数据量 × 30 × 回看比例
月度传输量 = 月度检索量
```
