## 后端优化

### 1. 计算器基类增强 (`backend/app/services/calculator/base.py`)
**问题**: S3StandardCalculator 和 S3GlacierCalculator 中有大量重复的费用计算逻辑
**解决方案**:
- 在 BaseCalculator 中添加了 `_calculate_storage_costs()` 通用方法
- 统一处理 S3 Standard 和 Glacier IR 的费用计算
- 自动判断存储类型并计算相应的检索费用

**优化效果**:
- 减少约 50 行重复代码
- 两个子类计算器代码更简洁清晰
- 维护更容易，修改计算逻辑只需在一处更改

### 2. API 工具函数抽取 (`backend/app/api/utils.py`)
**问题**: 多个 API 路由中有重复的验证和错误处理逻辑
**解决方案**:
- 创建 `utils.py` 文件，提供通用工具函数
- 抽取 `validate_region()` 函数处理区域验证
- 抽取 `get_calculator()` 函数处理计算器选择逻辑
- 抽取 `handle_calculation_error()` 函数统一错误处理

**优化效果**:
- 减少重复代码约 30 行
- API 路由更专注于业务逻辑
- 错误处理更一致

### 3. 生命周期计算器重构 (`backend/app/services/calculator/lifecycle.py`)
**问题**: `_calculate_stage_cost()` 方法过于复杂，超过 100 行
**解决方案**:
- 拆分为 4 个独立的辅助方法：
  - `_calculate_stage_storage_cost()` - 计算存储费用
  - `_calculate_stage_request_cost()` - 计算请求费用
  - `_calculate_stage_retrieval_cost()` - 计算检索费用
  - `_calculate_stage_transition_cost()` - 计算转换费用

**优化效果**:
- 每个方法职责单一，更易理解
- 提高代码可测试性
- 便于独立修改各项费用计算逻辑

## 前端优化

### 1. 表单验证工具函数 (`frontend/src/utils/validation.ts`)
**问题**: 多个表单组件中有重复的输入验证逻辑
**解决方案**:
- 创建统一的验证工具函数库
- 提供 `validateNumericField()` 处理数值验证
- 集中管理字段约束配置 `FIELD_CONSTRAINTS`
- 提供批量验证和格式化函数

**优化效果**:
- 减少重复验证代码约 40 行
- 验证规则统一管理
- 更容易添加新的验证规则

### 2. 表单标签组件 (`frontend/src/components/common/FormLabel.tsx`)
**问题**: 表单中大量重复的 Tooltip 和 QuestionCircleOutlined 使用
**解决方案**:
- 创建统一的 FormLabel 组件
- 封装标签、提示信息和必填标记
- 统一样式和交互行为

**优化效果**:
- 减少重复的 JSX 代码
- 统一的用户体验
- 更容易维护和修改样式

### 3. 表单常量管理 (`frontend/src/constants/forms.ts`)
**问题**: 表单选项、提示信息等硬编码在组件中
**解决方案**:
- 创建集中的常量配置文件
- 定义所有表单选项配置
- 集中管理提示文本
- 提供默认值配置

**优化效果**:
- 消除硬编码，提高可维护性
- 便于国际化和文案修改
- 选项配置可复用
